# useful-views

`useful-views` is a small Python package that gives a data project a fixed
structure, so that every derived table (a "useful view") records the recipe
that made it.

> **Status: design stage.** The package is not built yet. `SPEC.md` is the
> build specification and `reference/` is a worked example of the structure
> below.

## The structure

Using `useful-views` in a data project results in this layout:

```
my-data-project/
├── README.md                     # written by humans; documents the data project
├── datapackage.json              # generated: resources and recipes (never hand-edited)
├── .gitignore                    # generated by init: ignores raw/ contents and work/
│
├── raw/                          # raw inputs: git-ignored, never written by a recipe
│   ├── .gitkeep                  # keeps the folder in git
│   └── daily.csv
│
├── recipes/                      # written by humans, with or without AI tools
│   ├── monthly_stats/            # one folder = one recipe
│   │   ├── recipe.toml           # description, inputs, outputs
│   │   ├── 01_add_returns.py     # one file = one step; top comment is its description
│   │   ├── 02_monthly_aggregate.py
│   │   └── 03_rolling_average.py
│   │
│   └── volatility_flags/         # a second recipe, taking a view as its input
│       ├── recipe.toml           # inputs = ["useful-views/monthly-stats.parquet"]
│       └── 01_flag_months.py     # smallest valid recipe: one step file
│
├── work/                         # intermediates, never recorded, git-ignored
│   ├── monthly_stats/            # one scratch folder per recipe, emptied before each run
│   │   ├── daily_with_returns.parquet
│   │   └── monthly.parquet
│   └── volatility_flags/
│
└── useful-views/                 # declared outputs only, flat
    ├── README.md                 # generated: catalog of the views and how each was made
    ├── monthly-stats.parquet     # produced by recipes/monthly_stats
    └── volatility-flags.parquet  # produced by recipes/volatility_flags
```

## Vocabulary

In this repo, we establish how to document the creation of a useful view.
There are a few new vocabulary terms as a result.

**Raw input**: a file in `raw/`. Nothing in `raw/` is produced by a recipe.

**Recipe**: a recipe, like in the kitchen, is made up of steps. It is a
folder in `recipes/`. From the inputs it declares, it produces the useful
views it declares, by running its steps in order.

**Step**: each step in your flow does at least one non-trivial action on the
data. A step is one file in a recipe folder. For example, in polars, given:

```python
df = pl.DataFrame(
    {
        "foo": [-20.5, float("nan"), 80.0],
        "bar": [float("nan"), 110.0, 25.5],
        "ham": ["xxx", "yyy", None],
    }
)
```

calling `polars.DataFrame.drop_nans()` returns:

```
>>> df.drop_nans()
shape: (1, 3)
┌──────┬──────┬──────┐
│ foo  ┆ bar  ┆ ham  │
│ ---  ┆ ---  ┆ ---  │
│ f64  ┆ f64  ┆ str  │
╞══════╪══════╪══════╡
│ 80.0 ┆ 25.5 ┆ null │
└──────┴──────┴──────┘
```

This would be considered a step. So, again, a step is at least one
non-trivial transformation action on the data. That is the minimum. There is
no maximum yet: a step may do many transformations, and the author decides
where one step ends and the next begins.

**Work**: intermediate files, in `work/<recipe>/`, read only by later steps
of the same recipe.

**Useful view**: a declared output of a recipe, in `useful-views/`. Every
view is produced by exactly one recipe. A view can be an input to another
recipe. Anything read from outside the recipe that made it must be a view,
not a work file.

## Writing a recipe

A recipe folder holds one `recipe.toml` and at least one step file.

`recipes/monthly_stats/recipe.toml`:

```toml
description = "Monthly high, SD and 3-month rolling average from daily prices."
inputs  = ["raw/daily.csv"]
outputs = ["useful-views/monthly-stats.parquet"]
```

`recipes/monthly_stats/01_add_returns.py`:

```python
# Compute daily simple returns from Close so volatility is scale-free.
import polars as pl

df = pl.read_csv("raw/daily.csv", try_parse_dates=True).sort("Date")
df = df.with_columns(ret=pl.col("Close").pct_change())
df.write_parquet("work/monthly_stats/daily_with_returns.parquet")
```

The conventions:

- Inputs and outputs are written as paths from the project root. The path in
  `recipe.toml` is the same path the step uses in its code.
- An input is a file under `raw/`, or a view under `useful-views/` made by
  another recipe.
- An output is always a file directly inside `useful-views/`.
- Step files are named `NN_name.py` and run in numeric order.
- The comment at the top of a step file is its description. It is required.
- A step is an ordinary script. It runs from the project root and does not
  import `useful_views`. Use whichever data library you like.
- Steps pass data to each other only through files in `work/<recipe>/`.

## Commands

| Python | Command line | What it does |
|---|---|---|
| `init()` | `useful-views init` | Create the structure above. |
| `new_recipe(name)` | `useful-views new-recipe <name>` | Create a recipe folder with a template `recipe.toml` and one stub step. |
| `run(recipe)` | `useful-views run <recipe>` | Run a recipe's steps in order and record what it produced. |
| `check()` | `useful-views check` | Report missing inputs, missing views, recipes never run, and stray files. |
| `root()` | none | Return the project root, for building paths in a notebook. |

## Who writes what

Humans write the project `README.md` and everything in `recipes/`. The
package writes `datapackage.json`, `useful-views/README.md` and `.gitignore`.
No file has two authors.
